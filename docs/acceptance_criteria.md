# Acceptance Criteria

Эти критерии описывают наблюдаемое базовое поведение Task Tracker, которое должно сохраняться при изменениях проекта. Это функциональные требования, а не утверждение о наличии автоматических тестов.

1. **Общие задачи.** Созданная задача доступна в представлениях приложения и её статус/зона соответствует выбранному представлению.
2. **Детали задачи.** Пользователь может открыть задачу и просмотреть или изменить её описание, чек-лист и ссылки.
3. **Перемещение между представлениями.** Пользователь может переместить карточку между зонами матрицы Эйзенхауэра и колонками Kanban; после перемещения задача отображается в целевом статусе.
4. **Pomodoro.** Пользователь может запустить рабочий интервал и перерыв; по завершении интервала приложение сигнализирует об этом доступным для данной версии способом.
5. **Сохранение.** Задачи и настройки сохраняются и остаются доступными после перезапуска в соответствующем профиле браузера или Windows.

Критерии сформулированы по документации проекта в [`win32/README.md`](../win32/README.md) и проверяемы вручную. До появления тестового набора их проверка выполняется вручную; фактические результаты нужно фиксировать отдельно после каждого прогона.
