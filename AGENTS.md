# AGENTS.md — Инструкции для AI-ассистента

## Назначение проекта

Task Tracker — персональный трекер задач с матрицей Эйзенхауэра, Kanban-доской, Pomodoro-таймером и рабочим пространством для заметок и секретов. Репозиторий содержит две самостоятельные версии: веб-приложение в одном HTML-файле и нативное WPF-приложение для Windows.

## Архитектура и структура

- `win32/index.html` — веб-версия без внешних зависимостей; данные хранятся в `localStorage` браузера.
- `win32/src/App.cs` — точка входа нативного приложения.
- `win32/src/Store.cs` — модель и хранение задач, настроек, заметок и секретов; данные сохраняются в `%APPDATA%\TaskTracker\data.json` или в каталоге из `TASKTRACKER_DATA_DIR`.
- `win32/src/Boards.cs`, `Details.cs`, `Workspace.cs` — доски и интерфейс задач, деталей и рабочего пространства.
- `win32/src/Pomodoro.cs`, `Notifier.cs` — таймер и уведомления.
- `win32/src/MainWindow.cs`, `Theme.cs`, `SettingsView.cs`, `Ui.cs` — главное окно, темы, настройки и элементы интерфейса.
- `win32/build.cmd` — сборка нативной версии компилятором C# из установленного .NET Framework.
- `win32/tools/make-icon.ps1` — генерация иконки приложения.
- `task_manager_description.md`, `win32/feature_document_02.md` — исходные спецификации приложения.
- `docs/assignment_05_context_for_ai.md` — требования учебного задания.

В репозитории не обнаружены отдельные каталоги тестов, манифесты внешних зависимостей или команды lint/typecheck. Не заявляй наличие таких проверок без фактического подтверждения.

## Окружение и команды

Для нативной версии требуется Windows и установленный .NET Framework 4.x с компилятором `csc.exe`; приложение нацелено на .NET Framework 4.8. Отдельные пакеты устанавливать не требуется.

Команды запускать из PowerShell:

- Веб-версия: открыть `win32/index.html` в браузере. Для отдельного окна Edge можно запустить `Start-Process msedge "--app=file:///C:/projects/TaskBoot-homework/win32/index.html"` (путь поправить под расположение клона).
- Сборка нативной версии: `Set-Location win32; .\build.cmd` (результат `win32/bin/TaskTracker.exe`).
- Запуск после сборки: `Start-Process .\bin\TaskTracker.exe` из каталога `win32`.
- Автоматические тесты, линтер, проверка типов и отдельная команда установки зависимостей в текущей структуре не определены.

Сборка создаёт `win32/bin/`, который исключён из Git. Не утверждай, что сборка или приложение работают, пока соответствующая команда действительно не выполнена.


## Соглашения и проверка изменений

- Делай минимальные изменения по задаче и сохраняй текущие соглашения языка: C# в `win32/src/`, HTML/CSS/JavaScript в `win32/index.html`, PowerShell в `.ps1`.
- Не добавляй зависимости, тестовые фреймворки или инструменты без необходимости для задачи и явного согласования.
- Для изменений поведения укажи подходящую ручную проверку; автоматические тесты добавляй, если в проекте появится или уже доступен подходящий механизм.
- Фиксируй точные выполненные команды и их фактический вывод. Разделяй подтверждённые факты, гипотезы и непроверенные предложения.
- Перед завершением покажи `git diff` и кратко перечисли изменённые файлы. Не включай в коммит посторонние пользовательские изменения.

## Запрещённые действия и безопасность

- Не читай, не создавай, не выводи в лог и не коммить реальные секреты, учётные данные или персональные данные. Используй только явно фиктивные примеры.
- Секреты в приложении хранятся незашифрованными (`localStorage` в веб-версии и `data.json` в нативной); не представляй приложение как менеджер паролей и не сохраняй настоящие секреты при проверках.
- Не выполняй production-деплой, операции с боевыми данными или отправку пользовательских данных на внешние сервисы.
- Не выполняй деструктивные команды и операции Git, удаляющие или переписывающие историю/данные (например, `git reset --hard`, `git clean -fd`, `git push --force`).
- Не меняй зависимости или системные настройки без необходимости и согласования.
- Во время явно заданного read-only аудита не изменяй файлы, не запускай сборки, тесты или другие команды, меняющие состояние.
- Не указывай AI-ассистента соавтором Git-коммита: не добавляй `Co-authored-by` trailer или иные авторские атрибуции для ИИ. Используй настроенную человеческую Git-идентичность владельца репозитория; не подменяй автора коммита.

## Review gates

1. До правок проверь `git status` и сохрани все уже существующие изменения пользователя.
2. Сверь proposed diff с задачей; не включай несвязанные изменения.
3. Передай человеку diff и точные команды проверки. Не заявляй результат проверки, которую не запускал.
4. Коммит, публикация или интеграция изменений выполняются только в рамках прямого запроса пользователя; перед коммитом проверь состав staged-файлов.
